# M Justice Partners — โครงสร้างระบบใหม่

เอกสารนี้สรุปสิ่งที่เปลี่ยนจากไฟล์เดิม (`index.html` ไฟล์เดียว ~1,300 บรรทัด
ผสม HTML/CSS/JS ทั้งหมด) มาเป็นโครงสร้างแบบแยกส่วน และแนวทางขยายระบบ
ไปสู่ระดับองค์กรที่ใหญ่ขึ้น

## 1. โครงสร้างไฟล์ใหม่

```
justiceflow/
├── index.html              โครง HTML ล้วนๆ ไม่มี logic ฝังอยู่เลย
├── css/
│   └── app.css              สไตล์เสริมนอกเหนือจาก Tailwind
└── js/
    ├── config.js             การเชื่อมต่อ Supabase + ตารางค่าคงที่กลาง
    ├── utils.js               escapeHtml, format วันที่/เงิน, debounce, toast
    ├── state.js               state กลางของแอป (แทน global variable)
    ├── app.js                 จุดเริ่มต้น: bootstrap + ผูก event ทั้งหมด
    ├── api/
    │   ├── cases.js           query ทั้งหมดของตาราง cases
    │   ├── schedules.js       query ทั้งหมดของตาราง schedules
    │   └── contacts.js        query ทั้งหมดของตาราง contacts
    └── ui/
        ├── dashboard.js       การ์ดสถิติ + ตารางนัดหมายใกล้ถึง
        ├── casesTable.js      ตารางทะเบียนคดี + เพจจิเนชัน
        ├── caseModals.js      modal เพิ่ม/แก้ไข/อัปเดตสถานะ/ลงนัด/ดูรายละเอียด
        ├── contacts.js        หน้าสมุดรายชื่อ + modal ผู้ติดต่อ
        └── router.js          สลับหน้าคดีความ <-> สมุดรายชื่อ
```

**หลักการแบ่งเลเยอร์:** `ui/*` ห้ามคุยกับ Supabase ตรงๆ ต้องผ่าน `api/*`
เท่านั้น และ `api/*` ห้ามยุ่งกับ DOM เลย ทำให้แก้ schema ฐานข้อมูล
หรือเปลี่ยนหน้าตา UI แยกจากกันได้โดยไม่กระทบกัน และเทสต์แต่ละเลเยอร์
แยกกันได้

## 2. บั๊ก/ปัญหาที่พบและแก้ไขแล้ว

| ปัญหา | ผลกระทบ | วิธีแก้ |
|---|---|---|
| หน้า "คดีความ" ไม่มี `id="casesPage"` แต่ `switchPage()` พยายามหา id นี้ | สลับไปหน้าสมุดรายชื่อแล้วเนื้อหาคดีความไม่ถูกซ่อน ซ้อนกันสองหน้า | ครอบเนื้อหาคดีความด้วย `<div id="casesPage">` จริง |
| ยัดข้อมูลจากฐานข้อมูล (คำบรรยายคดี, ชื่อคู่ความ) ลง `innerHTML` โดยไม่ escape | **Stored XSS** — ถ้ามีคนกรอกคำบรรยายคดีเป็นแท็ก `<script>`/`<img onerror>` โค้ดจะรันทันทีในเบราว์เซอร์ของทุกคนที่เปิดดูคดีนั้น | เพิ่ม `escapeHtml()` ใช้กับทุกจุดที่แสดงข้อมูลจากฐานข้อมูล |
| ยัดข้อมูล (ชื่อคู่ความ, คำบรรยาย) ลงใน attribute `onclick="fn('...', \`${desc}\`)"` ตรงๆ | ถ้าข้อมูลมี backtick/quote จะทำให้ HTML พัง หรือรันโค้ดแปลกปลอมผ่าน attribute ได้ | เปลี่ยนเป็น event delegation ด้วย `data-index` แล้วดึง object จริงจาก state แทน |
| ตัวกรองสถานะ/ค้นหา ไม่ reset หน้ากลับไปหน้า 1 | เปลี่ยนตัวกรองแล้วอาจค้างอยู่หน้า 5 ทั้งที่ผลลัพธ์ใหม่มีแค่ 2 หน้า → เห็นตารางว่าง | `resetToFirstPage()` ทุกครั้งที่เปลี่ยนคำค้นหา/ตัวกรอง |
| ช่องค้นหาด่วนยิง query ทุกครั้งที่กดแป้นพิมพ์ | เปลือง request, ฐานข้อมูลโดนถล่มตอนพิมพ์เร็ว | เพิ่ม `debounce()` 300ms |
| ใช้ `alert()` บล็อกหน้าจอทุกครั้งที่บันทึก/error | ดูไม่เป็นมืออาชีพ, ขวางการทำงานต่อเนื่อง | เปลี่ยนเป็น toast แจ้งเตือนมุมขวาบน หายเองใน 3 วิ |
| `toggleContactModal` และตัวแปร metrics/สถานะถูกประกาศซ้ำ 2 รอบในไฟล์เดิม | โค้ดชุดหลังทับชุดแรกเงียบๆ debug ยาก | รวมเป็นฟังก์ชันเดียวต่อหน้าที่ ไม่มีการประกาศซ้ำ |
| ค่าคงที่ (สถานะ, สี, ป้ายภาษาไทย) กระจาย 5-6 จุด | เพิ่มสถานะใหม่ 1 อันต้องแก้ 6 ที่ พลาดง่าย | รวมไว้ที่ `config.js` จุดเดียว |

## 3. อัปเดต: ระบบ Auth + Multi-tenant + Audit Log (ทำเสร็จแล้ว)

หัวข้อ 3-4 ที่เคยเป็นแค่ "แนวทาง" ด้านล่าง ตอนนี้ implement จริงแล้ว
ทั้งฝั่งฐานข้อมูล (`sql/`) และฝั่งหน้าเว็บ (`js/api/auth.js`,
`js/ui/login.js`, และ role-gating ใน `caseModals.js`)

### 3.1 ต้องรันอะไรบ้างก่อนใช้งานได้จริง

**ขั้นตอนที่ 1 — รัน SQL migration ตามลำดับ** ใน Supabase Studio →
SQL Editor (ห้ามสลับลำดับ เพราะแต่ละไฟล์อ้างอิงของไฟล์ก่อนหน้า):

| ไฟล์ | ทำอะไร |
|---|---|
| `sql/001_multi_tenant_schema.sql` | สร้างตาราง `organizations`, `profiles` + เพิ่ม `organization_id`/`assigned_lawyer_id` ในตารางเดิม + backfill ข้อมูลเก่าเข้าสำนักงานเดียว + trigger สร้างโปรไฟล์อัตโนมัติตอนสมัคร |
| `sql/002_row_level_security.sql` | เปิด RLS ทุกตาราง + policy จำกัดสิทธิ์ตาม organization และ role |
| `sql/003_audit_log.sql` | สร้างตาราง `case_activity_log` + trigger บันทึกอัตโนมัติทุกครั้งที่สร้าง/แก้ไข/เปลี่ยนสถานะคดี |
| `sql/004_search_rpc.sql` | เพิ่ม full-text search index + ฟังก์ชัน `search_cases()` แทนการต่อสตริง `.or()` ฝั่ง client แบบเดิม |
| `sql/005_fix_new_user_trigger.sql` | แก้บั๊ก "Database error creating new user" — ทำให้ trigger สร้างโปรไฟล์ทนกว่าเดิม (ดูหัวข้อ "ปัญหาที่พบระหว่างติดตั้ง" ด้านล่าง) |

⚠️ ก่อนรัน `001` ให้แก้ชื่อสำนักงานในบรรทัด
`insert into organizations (...) values ('...', 'M Justice Partners')`
ให้ตรงกับชื่อจริง ค่า UUID `00000000-0000-0000-0000-000000000001`
คงไว้ตามเดิมได้ (เป็นแค่ id ของสำนักงานแรกที่ backfill ข้อมูลเก่าเข้าไป)

**ขั้นตอนที่ 2 — เปิด Supabase Auth** (Authentication → Providers →
เปิด Email) แล้วสร้างผู้ใช้อย่างน้อย 1 คนให้ทีม (Authentication → Users
→ Add user) — trigger จาก `001` จะสร้างโปรไฟล์ให้อัตโนมัติเป็น role
`lawyer` ในสำนักงานที่ backfill ไว้ ถ้าต้องการเปลี่ยนเป็น `admin`/`partner`
ให้แก้ตรงในตาราง `profiles` ผ่าน SQL Editor โดยตรง (การเลื่อนขั้น role
ตั้งใจไม่เปิดให้ทำผ่านหน้าเว็บ เพื่อกันคนเลื่อนขั้นตัวเอง)

**ขั้นตอนที่ 3 — เปิดเว็บ** ตอนนี้หน้าแรกจะเป็นหน้าล็อกอินเสมอ กรอก
อีเมล/รหัสผ่านที่สร้างไว้ในขั้นตอนที่ 2 เพื่อเข้าใช้งาน

### 3.2 สิ่งที่เปลี่ยนไปฝั่งหน้าเว็บ

- `js/api/auth.js` — signIn/signOut/getSession/ดึงโปรไฟล์
- `js/ui/login.js` — หน้าจอล็อกอิน + สลับแสดง `#loginScreen`/`#appShell`
- `state.currentUser` — เก็บ `userId`, `organizationId`, `role`,
  `fullName` ของผู้ที่ login อยู่ ทุกจุดที่สร้างข้อมูลใหม่ (คดี/นัดหมาย/
  คู่ความ) จะแนบ `organization_id` นี้ไปด้วยเสมอ
- ตัวเลือก "Closed (ปิดสำนวนคดีถาวร)" ในหน้าต่างอัปเดตสถานะจะถูก
  `disabled` โดยอัตโนมัติถ้า role ของผู้ login เป็น `lawyer`/`paralegal`
  (สอดคล้องกับ RLS policy ที่บล็อกไว้อีกชั้นในฐานข้อมูล — ฝั่งหน้าเว็บ
  แค่ซ่อนไว้ไม่ให้เจอ error ที่งงว่าทำไมกดไม่ได้)
- หน้าต่างรายละเอียดคดีเพิ่มส่วน "🕘 ประวัติการแก้ไข (Audit Trail)"
  ดึงจาก `case_activity_log` ที่ฐานข้อมูลบันทึกให้อัตโนมัติ
- การค้นหาด่วนในทะเบียนคดีตอนนี้เรียก RPC `search_cases()` แทนการต่อ
  สตริง `.or()` แบบเดิม (เร็วขึ้นเมื่อข้อมูลเยอะ + ปลอดภัยขึ้น)

### 3.3 สิ่งที่ยังไม่ได้ทำ (ขั้นต่อไปถ้าต้องการ)

- **หน้า admin จัดการผู้ใช้** — ตอนนี้การเพิ่มผู้ใช้ใหม่/เปลี่ยน role
  ยังต้องทำผ่าน Supabase Studio โดยตรง ยังไม่มีหน้าเว็บให้ partner/admin
  จัดการเอง
- **มอบหมายคดีให้ทนายคนอื่น** — คอลัมน์ `assigned_lawyer_id` มีอยู่แล้ว
  ในฐานข้อมูล (ตอนนี้ตั้งเป็นผู้สร้างคดีอัตโนมัติ) แต่ยังไม่มี UI ให้เปลี่ยน
  ผู้รับผิดชอบคดีทีหลัง หรือกรอง "คดีของฉัน" บนแดชบอร์ด
- **Storage สำหรับไฟล์แนบคดี** และ **การแจ้งเตือนอัตโนมัติผ่านอีเมล/LINE**
  ยังเป็นแค่แนวทางในหัวข้อ 5 ด้านล่าง ยังไม่ implement

## 4. คงเหลือหลัง 001-005 (ตอนนี้ทำเพิ่มแล้วในหัวข้อ 5)

หัวข้อ "หน้า admin จัดการผู้ใช้/มอบหมายคดี" และ "ไฟล์แนบต่อคดี" ที่เคย
อยู่ในหัวข้อนี้ **ทำเสร็จแล้ว** — ดูรายละเอียดที่หัวข้อ 5 ด้านล่าง สิ่งที่
เหลือจริงๆ อยู่ในหัวข้อ 6

## 5. อัปเดต: หน้า Admin, มอบหมายคดี, และไฟล์แนบ (ทำเสร็จแล้ว)

ตามหัวข้อ 3.3 เดิม — สามอย่างนี้ implement ครบแล้ว (ไม่รวมระบบแจ้งเตือน
ตามที่ระบุให้ข้าม)

### 6.1 ต้องรัน SQL เพิ่มอีก 3 ไฟล์ (ต่อจาก 001-005 เดิม)

| ไฟล์ | ทำอะไร |
|---|---|
| `sql/006_invites_and_admin.sql` | ระบบคำเชิญผู้ใช้ใหม่ (แทนการใช้ service role key ที่ไม่ปลอดภัย), เพิ่ม role `pending` สำหรับผู้ที่สมัครเองโดยไม่มีคำเชิญตรงกัน, policy ให้ admin/partner เปลี่ยน role คนในสำนักงาน และ "ดึง" ผู้ใช้ที่ยังไม่สังกัดสำนักงานเข้ามา |
| `sql/007_case_assignment_search.sql` | ขยาย `search_cases()` ให้กรอง "คดีของฉัน" และส่งชื่อทนายผู้รับผิดชอบกลับมาด้วย |
| `sql/008_case_documents_storage.sql` | สร้าง Storage bucket `case-documents` (private) + ตาราง `case_documents` + RLS ที่แยกสิทธิ์ตามโฟลเดอร์ `organization_id` |

⚠️ **ทำไมไม่ใช้ Supabase Admin API สร้างผู้ใช้ตรงๆ จากหน้าเว็บ:** การสร้าง
ผู้ใช้ผ่าน Admin API ต้องใช้ **service role key** ซึ่งข้าม RLS ได้ทั้งหมด
ถ้าฝังในโค้ดฝั่ง client เท่ากับเปิดฐานข้อมูลทั้งก้อนให้ใครก็ได้ จึงออกแบบ
เป็น "ระบบคำเชิญ" แทน: admin/partner สร้างคำเชิญ (อีเมล+บทบาท) ไว้ล่วงหน้า
→ ผู้ถูกเชิญไปสมัครเองด้วย `supabase.auth.signUp()` ปกติ (ปลอดภัย ใช้
ANON KEY ได้) → trigger จับคู่อีเมลกับคำเชิญให้อัตโนมัติ ถ้าอีเมลไม่ตรงกับ
คำเชิญไหนเลย ผู้ใช้จะได้ role `pending` และเข้าแอปไม่ได้จนกว่า admin จะ
ไป "ดึงเข้าสำนักงาน" ที่หน้า จัดการผู้ใช้งาน ด้วยตัวเอง

### 6.2 หน้าจัดการผู้ใช้งาน (เมนู "🛠️ จัดการผู้ใช้งาน" — เห็นเฉพาะ admin/partner)

- เชิญผู้ใช้ใหม่ (อีเมล + บทบาท) พร้อมรายการคำเชิญที่ส่งไว้/ยกเลิกได้
- รายชื่อสมาชิกในสำนักงาน พร้อม dropdown เปลี่ยนบทบาทได้ทันที
- รายชื่อผู้ใช้ที่สมัครเองโดยไม่มีคำเชิญตรงกัน (`role = pending`) พร้อมปุ่ม
  "ดึงเข้าสำนักงาน" กำหนดบทบาทได้เลย

หน้าเข้าสู่ระบบเพิ่มลิงก์ "สมัครสมาชิกใหม่" (self-signup) และหน้า "รอการ
อนุมัติ" สำหรับผู้ใช้ที่ login สำเร็จแต่ยัง `pending` อยู่

### 6.3 มอบหมายคดีให้ทนายคนอื่น

- ฟอร์มเพิ่ม/แก้ไขคดี มี dropdown "มอบหมายให้ทนายความ" ดึงรายชื่อจาก
  สมาชิกในสำนักงาน (ตอนสร้างคดีใหม่ ค่าเริ่มต้นคือผู้สร้างเอง แก้ได้)
- ตารางทะเบียนคดีมีคอลัมน์ "มอบหมายให้" แสดงชื่อทนายผู้รับผิดชอบ
- checkbox "คดีของฉันเท่านั้น" ข้างตัวกรองสถานะ กรองเฉพาะคดีที่มอบหมาย
  ให้ผู้ login อยู่

### 6.4 ไฟล์แนบคดี

หน้าต่างรายละเอียดคดีเพิ่มส่วน "📎 ไฟล์แนบคดี" — อัปโหลด/ดาวน์โหลด/ลบไฟล์
ได้ (ลบได้เฉพาะคนอัปโหลดเองหรือ admin/partner) ไฟล์เก็บใน Storage bucket
ส่วนตัว (private) แยกสิทธิ์ตาม organization ผ่าน RLS ของ `storage.objects`
เอง — ดาวน์โหลดผ่าน signed URL ที่หมดอายุใน 60 วินาทีเสมอ ไม่มี public URL
ตรงๆ ให้เดา path เอาได้

## 6. สิ่งที่ยังไม่ได้ทำ

- **การแจ้งเตือนนัดหมายเชิงรุก** (ข้ามตามที่ระบุไว้) — ยังต้องเปิดหน้าเว็บ
  ถึงจะเห็นนัดที่ใกล้ถึง แนวทางเดิมยังใช้ได้: Supabase Edge Function +
  cron ส่งอีเมล/LINE Notify
- **SSO/2FA** — ยังไม่ implement ตามที่ระบุไว้ในหัวข้อเดิม

## 7. สิ่งที่ยังคงพฤติกรรมเดิมไว้ทั้งหมด

ฟีเจอร์ทุกอย่างที่มีอยู่เดิม (เพิ่ม/แก้ไขคดี, ลงนัดเพิ่ม, อัปเดตสถานะ,
ค้นหาคดีแบบพิมพ์กรองสด, สมุดรายชื่อคู่ความ, ผูกคู่ความเข้ากับคดี) ทำงาน
